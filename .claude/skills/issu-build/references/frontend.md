# 화면 · 목업 · 공개 경로

빌드가 없다. `hub.js`·`app.js`·`offering.js`·`readiness.js` 가 브라우저로 그대로 간다.

## 목업을 실서버와 맞춘다 — 가장 자주 데인 것

`scripts/mock-ui-server.js` 는 DB 없이 화면을 띄운다. **여기가 어긋나면 로컬 확인이
거짓말을 한다.** 여섯 번 데였다.

- **시드 값을 목업에 베껴 넣지 않는다.** 마이그레이션 SQL 을 **직접 판다.** 베끼면
  마이그레이션을 고쳤을 때 목업만 옛 값으로 남고, 로컬에서는 정상으로 보인다.
- 실서버가 검증하면 목업도 검증한다. 목업이 무조건 201 을 주면 폼 오류를 화면에서 못 본다.
- 실서버가 쿼리 파라미터를 읽으면 목업도 읽는다 (`GET /deals` 가 `q`/`stage`/`mine` 을
  무시해 「내 딜」 버튼이 로컬에서 죽어 있었다).
- 실서버가 새 컬럼에 기본값을 넣으면 목업도 넣는다.

**목업을 띄우기 전에 포트를 확인한다.** 4173 이 이미 떠 있으면 새 프로세스가
`EADDRINUSE` 로 죽고, **옛 코드로 확인하게 된다.**

```
lsof -ti:4173 | xargs kill 2>/dev/null
```

## `APP_SURFACE` 허용목록

`server.js` 의 `APP_SURFACE` 는 배포 표면을 가른다. 새 공개 경로를 만들면 여기 같이
넣는다. **빠뜨리면 로컬(`all`)은 멀쩡하고 프로덕션에서만 404** 다 — 배포 후에야 안다.

`robots.txt` 도 같이 본다. 개인 결과 링크 같은 것은 `Disallow` 한다.

## `hub.js` 렌더

문자열을 만들어 `innerHTML` 로 넣는다. 그래서 —

- **`renderStage()` 를 함부로 부르지 않는다.** 부르면 `<details>` 가 접히고 스크롤이 튄다.
  요약만 갈아끼우는 좁은 갱신 함수를 따로 둔다 (`renderInquiryProductChips()` 선례).
- 같은 값을 **두 곳에 그리면 갱신도 두 곳을 같이** 한다. 한쪽만 옛 숫자로 남는다
  (`renderStallSummary()` 가 STEP01 과 컨텍스트 카드를 같이 고친다).
- 사용자 입력은 `escapeHtml()` 를 통과시킨다.
- 같은 계산을 화면과 문서가 따로 하지 않는다 — 숫자가 갈린다.

## 툴팁

**네이티브 `title` 을 쓰지 않는다.** 뜨는 데 1초쯤 걸리고 줄바꿈·폭을 못 잡아서
"마우스를 올려도 아무 반응이 없다"로 읽힌다. `data-hint` + CSS `::after` 를 쓴다
(`white-space: pre-line`, `cursor: help`, `tabindex="0"`). 단 `overflow` 가 자르는
컨테이너(`.deal-card-list`) 안에서는 꺼 둔다.

## 분류 어휘는 `taxonomy.js` 한 곳

업종·규모 같은 목록을 화면마다 적으면 **반드시 갈린다.** 값이 갈리면 필터가 조용히
0건을 낸다. 폼과 허브가 같은 상수를 쓴다 (`TIMELINE_OPTIONS` 선례 — 진단 폼과 딜 화면).

## 규칙은 `lib/` 로 뺀다

서버·목업·검사가 **같은 규칙**을 쓰게 하려면 순수 함수여야 한다. DB 도 DOM 도 모르게
쓴다. `lib/case-match.js`·`lib/readiness-scoring.js`·`lib/handoff-snapshot.js` 가 그렇다.

목업에 없는 라우트에 규칙을 넣으면 **로컬 확인이 불가능해진다.**

## 상태를 지어내지 않는다

값이 없으면 없다고 그린다. `stage_changed_at` 이 없는 041 이전 딜은 단계 시계를
**안 그린다.** `inquiry_date` 가 없으면 `created_at` 을 쓰되 **라벨을 「등록」으로 바꾼다** —
없는 것을 있는 척하지 않는다.
