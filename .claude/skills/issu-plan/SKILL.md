# 기획

코드를 쓰기 전에 읽는다. **구현은 `issu-build`** 가 받는다.

## 기획서 골격 — 이 순서를 지킨다

```
Context          왜 지금. 무엇을 만들지가 아니라 무엇이 문제인지
관통하는 원칙      이 판 전체를 지배하는 판단 2~4개
Phase N          혼자 배포해도 안전한 단위로
고칠 파일         표로
검증             종단 확인 절차 + 단위 검사 목록
하지 않는다        표로. **생략 금지**
```

### `Context` 는 문제로 시작한다

"X 기능을 추가한다"가 아니라 "지금 Y 를 못 해서 Z 가 벌어진다"로 쓴다. 조사 중에 나온
**결정적 사실**이 있으면 여기 적는다 — 그게 기획 전체를 뒤집는 경우가 많다.

> 예: 「42문항과 인계 키트는 다른 질문을 한다」를 Context 에 적었더니 "자동으로 다
> 채운다"는 요구가 "채워진 것 + 무엇을 물어야 하는지"로 바뀌었다.

### `하지 않는다` 표가 필수다

없으면 범위가 조용히 넓어진다. **안 하기로 한 것과 그 이유**를 남기면 나중에 같은
논의를 다시 안 한다. 실제로 이 표에서 나온 판단들:

| 안 한 것 | 이유 |
|---|---|
| `readiness_offering_weights` 새 표 | `packages.readiness_coverage` 가 이미 6축을 덮는다. 새 표는 새 검토 병목이다 |
| 서버에서 PDF 생성 | CJK 폰트 embed 는 용량·라이선스 별건. 링크로 대체 |
| 스팸 리드 자동 삭제 | 표시만 한다. 버리면 진짜 고객을 잃는다 |
| 고객 문서에 확정 금액 | 실단가 확정 전까지 「별도협의」 |

### Phase 는 혼자 배포해도 안전한 단위로

Phase 1 만 배포된 상태에서 화면이 정상이어야 한다. 마이그레이션이 아직 안 돌아간
구간도 마찬가지다(`hasColumn`).

## 코드를 쓰기 전에 반드시 답하는 일곱 가지

### 1. 이미 있는 것으로 되나?

새 표·새 컬럼은 **새 검토 병목**이다. 누군가 그걸 채워야 하고, 안 채워지면 기능이
조용히 죽는다. 기존 데이터로 되는지 먼저 본다.

### 2. 마이그레이션이 필요한가 — 시드인가 스키마인가?

- **스키마만**(`alter table … add column`) → `scripts/apply-migrations.js` 목록에 넣는다
- **시드**(`insert`/`update` 로 값을 넣음) → **넣지 않는다.** 어드민에서 고친 값을 덮는다

### 3. 되돌릴 수 있나?

없으면 파일 상단에 **「적용 전 확인」 쿼리**를 적는다. 세 값이 전부 0 이어야 실행하는
식으로. `db/migrations/040_drop_fqa.sql` 이 선례다.

### 4. 개인정보가 늘어나나?

늘면 **셋을 같이** 센다 — `readiness.html` 고지 문구 · `routes/hub.js` 의
`PRIVACY_NOTICE.version` · 검사. 항목만 늘리고 고지를 안 고치면 동의 범위를 벗어난다.
UI 문제가 아니라 법적 문제다. 상세는 `issu-build/references/privacy.md`.

### 5. 새 공개 경로가 있나?

`server.js` 의 `APP_SURFACE` 허용목록을 같이 고친다. 빠뜨리면 **로컬(`all`)은 멀쩡하고
프로덕션에서만 404** 다 — 배포 후에야 안다.

### 6. 고객이 보는 문서에 들어가나?

들어가면 **내부 필드를 안 부르는 구조**로 짠다. 플래그로 갈라 쓰면 언젠가 샌다.
`buildCustomerKit()`(`hub.js`)이 선례 — opinion·tech_note·단가·연락처를 **읽지 않는다**.

### 7. 목업으로 확인되나?

`npm run mock` 으로 못 보는 기능은 로컬 확인이 불가능하다. 규칙을 **`lib/` 의 순수
함수로 빼면** 서버·목업·검사가 같은 것을 쓴다. `lib/case-match.js`·`lib/handoff-snapshot.js`
가 그 이유로 만들어졌다.

## 사람이 확정해야 하는 것은 따로 모은다

개발로 못 메우는 것을 개발로 메우려 하면 **그럴듯한 가짜**가 들어간다. 기획서에
「확인 필요」로 묶어 내고 누가 답해야 하는지 적는다.

지금 열려 있는 것들 — 실단가(ISV BU) · 정체 판정 기준일(영업 리더) · 처방문 42개 문안
(ISV BU) · 메일 발송 수단 · 레퍼런스 사례 입력과 실명 공개 승인.

---

## 기획이 끝나면

`ExitPlanMode` 로 승인을 받고 **`issu-build`** 로 넘어간다. 승인 없이 코드를 쓰지 않는다.
